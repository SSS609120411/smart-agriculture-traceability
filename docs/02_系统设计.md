# 智慧农产品溯源管理系统 — 系统设计

## 1. 总体架构

系统采用 **前后端分离** 的 B/S 架构：

```
┌──────────────┐        HTTP/JSON         ┌──────────────┐      ┌──────────────┐
│  浏览器前端   │  ──────────────────────▶ │  Flask 后端   │ ───▶ │    MySQL     │
│  Vue3 + Vite │  RESTful API (/api/*)    │  业务逻辑     │ ORM  │   数据库     │
│ Element Plus │                          │  JWT 鉴权     │      │              │
└──────────────┘                          └──────────────┘      └──────────────┘
```

- **前端**：Vue 3 单页应用（SPA），开发态由 Vite 代理 `/api`、`/static` 到后端，实现同源访问。
- **后端**：Flask 提供 RESTful 接口，采用蓝图（Blueprint）按模块组织；SQLAlchemy 做 ORM；PyJWT 做无状态认证。
- **数据库**：MySQL，通过 PyMySQL 驱动连接；引擎可配置，便于测试环境切换 SQLite。

## 2. 技术选型

| 层 | 技术 | 选型理由 |
|----|------|----------|
| 前端框架 | Vue 3（组合式 API） | 生态成熟、开发效率高 |
| 构建工具 | Vite | 启动快、配置简单 |
| UI 组件库 | Element Plus | 中文文档完善、组件丰富 |
| 状态管理 | Pinia | Vue 3 官方推荐，轻量 |
| 图表 | ECharts | 统计可视化 |
| 后端框架 | Flask | 轻量、灵活 |
| ORM | Flask-SQLAlchemy | 简化数据库操作 |
| 认证 | PyJWT | 无状态令牌，前后端分离适配 |
| 二维码 | qrcode | 生成溯源二维码 |

## 3. 模块划分

```
智慧农产品溯源管理系统
├── 认证模块（auth）       登录 / 注册 / 当前用户
├── 用户管理模块（users）  管理员维护用户与角色
├── 分类模块（categories） 产品分类 CRUD
├── 产品模块（products）   产品 CRUD
├── 批次模块（batches）    批次 CRUD + 溯源码/二维码生成
├── 记录模块（records）    五个环节记录的新增/查询/删除
├── 溯源模块（trace）      公开溯源查询 + 查询日志
└── 看板模块（dashboard）  统计聚合
```

## 4. 详细设计

### 4.1 认证与鉴权流程

1. 用户提交用户名密码，后端校验后用 `PyJWT` 签发令牌（`sub`=用户 id、`role`=角色、`exp`=过期时间）。
2. 前端将令牌存入 `localStorage`，请求时通过 Axios 拦截器在 `Authorization: Bearer <token>` 头携带。
3. 后端通过 `login_required` / `role_required` 装饰器校验令牌与角色，校验通过后将用户对象挂载到 `g.user`。

### 4.2 溯源码与二维码生成

- **溯源码**：格式 `TR + 时间戳(YYYYMMDDHHMMSS) + 6 位随机字符`，如 `TR20260929214156Y1HDCB`，全局唯一。
- **二维码**：内容为溯源页 URL（`TRACE_PAGE_PREFIX + 溯源码`），用 `qrcode` 库生成 PNG，保存到 `backend/static/qrcodes/`，前端通过 `/static` 代理访问。

### 4.3 溯源查询流程

1. 消费者输入溯源码或扫描二维码，前端跳转 `/#/trace/<溯源码>`。
2. 前端调用 `GET /api/trace/<code>`（公开接口）。
3. 后端按溯源码查询批次，关联产品、分类、生产者，聚合五个环节记录，按时间排序生成时间轴。
4. 记录本次查询到 `trace_logs` 表，返回完整溯源数据。

## 5. 接口设计

统一响应格式：

```json
{ "code": 0, "message": "ok", "data": { } }     // 成功
{ "code": 400, "message": "错误信息" }           // 失败（code 同 HTTP 状态码）
```

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /api/auth/login | 登录 | 公开 |
| POST | /api/auth/register | 注册（消费者） | 公开 |
| GET | /api/auth/me | 当前用户信息 | 登录 |
| GET | /api/users | 用户列表 | 管理员 |
| POST | /api/users | 创建用户 | 管理员 |
| PUT | /api/users/{id} | 更新用户 | 管理员 |
| DELETE | /api/users/{id} | 删除用户 | 管理员 |
| GET | /api/categories | 分类列表 | 登录 |
| POST | /api/categories | 新增分类 | 管理员 |
| PUT | /api/categories/{id} | 更新分类 | 管理员 |
| DELETE | /api/categories/{id} | 删除分类 | 管理员 |
| GET | /api/products | 产品列表（可按分类筛选） | 登录 |
| POST | /api/products | 新增产品 | 管理员/生产者 |
| PUT | /api/products/{id} | 更新产品 | 管理员/生产者 |
| DELETE | /api/products/{id} | 删除产品 | 管理员/生产者 |
| GET | /api/batches | 批次列表（生产者只看自己） | 登录 |
| POST | /api/batches | 创建批次 | 管理员/生产者 |
| GET | /api/batches/{id} | 批次详情 | 登录 |
| PUT | /api/batches/{id} | 更新批次 | 管理员/生产者 |
| DELETE | /api/batches/{id} | 删除批次 | 管理员/生产者 |
| GET | /api/batches/{id}/qrcode | 获取二维码信息 | 登录 |
| GET | /api/batches/{id}/records/{stage} | 某环节记录列表 | 登录 |
| POST | /api/batches/{id}/records/{stage} | 新增环节记录 | 管理员/生产者 |
| DELETE | /api/batches/records/{stage}/{rid} | 删除环节记录 | 管理员/生产者 |
| GET | /api/trace/{code} | 溯源查询 | 公开 |
| GET | /api/dashboard/stats | 看板统计 | 登录 |

> `stage` 取值：`planting` / `quality` / `processing` / `logistics` / `sales`。

## 6. 前端设计

- **路由**：采用 Hash 路由（`createWebHashHistory`），便于二维码直接指向 `/#/trace/<code>`。
- **权限守卫**：`router.beforeEach` 校验令牌与角色，未登录跳转登录页，越权访问重定向看板。
- **页面**：登录 / 注册 / 数据看板 / 产品分类 / 产品管理 / 批次管理 / 批次详情 / 用户管理 / 溯源查询。
- **布局**：`Layout.vue` 提供侧边栏 + 顶栏 + 主内容区，菜单按角色动态渲染。
